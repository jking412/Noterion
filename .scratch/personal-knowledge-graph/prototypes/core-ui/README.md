# Noterion 核心桌面体验原型（Issue #1）

这是一组可以丢弃的界面原型，回答“搜索、图谱、完整描述和资料入口应该怎样组合”。三个方案共用同一份固定演示数据，切换方案不会产生三份知识点。没有选定胜出方案；选择与组合方案属于 [Issue #2](https://github.com/jking412/Noterion/issues/2)。

主技能：Matt 的 `prototype`，已按 `UI.md` 制作同一路径上的三个独立布局、`?variant=` 和浮动切换条。`frontend-design` 用于视觉层级、字号、颜色和三套布局的区分。没有套用生产应用或 TDD 工作流。Sites 仅提供本人私有的静态演示入口。

## 固定演示场景

11 个知识点、4 个主题入口、2 份虚构 HTML 文件资料、2 个公开 Docker 文档链接。文件在 `assets/` 中，是能实际打开的只读样本，不伪装成已上传的 PDF 或对象存储文件。

1. **描述检索**：搜索 `docker exec` → 选择“进入容器终端” → 查看突出节点、完整描述与命令 → “查看”演示文件或“打开”外部文档。
2. **共享身份**：Docker 和 Linux 运维 → “容器排障”，均为 `troubleshoot`。编辑一次描述，从另一主题访问仍是相同内容、资料与身份。
3. **同名异义**：搜索 `锁`，分别选择 MySQL 的 `mysql-lock` 与并发编程的 `code-lock`。结果以所属主题与摘要区分，名称相同不归并。
4. **多词搜索**：搜索 `docker 锁`，切换“全部匹配 / 任意匹配”，观察结果改变。搜索只做名称与描述的片段包含，不解析资料正文。
5. **独立保存与图状态**：编辑并“保存修改（模拟）”，描述与搜索立即采用新内容，图显示“更新中”。点击“模拟图已赶上”后恢复图浏览和定位。
6. **图不可用**：底部“演示控制与状态”→“图服务不可用”。仍能搜索、编辑、阅读、打开资料；图定位明确不可用。先模拟恢复连接，仍处于更新中，再模拟赶上。
7. **主题删除**：在图中选择 Docker →“在图中删除主题”。确认后移除 Docker、进入容器终端、查看容器日志；“容器排障”保留且仅属于 Linux 运维，原有独立点和文件保留。图须模拟赶上才恢复浏览。
8. **普通知识点删除**：重置演示后，在图中删除“进入容器终端”，搜索其完整名称不再命中。演示文件仍能从资料库打开。

## 模拟边界

- 所有编辑、关系修改、删除、保存版本和图状态仅存在于当前页面内存。刷新或“重置全部演示数据”重新载入样本；这是原型控制，不是删除后恢复功能。
- 未连接个人数据、PostgreSQL、Neo4j、对象存储或 DeepSeek，没有正式持久化、真实上传、图同步或重建。
- 图不可用或未赶上时暂停图浏览和删除，保留搜索与描述。不会把图查询故障显示为“无关联”。
- 文件资料独立保留；description 是知识点属性；主图只展示知识点。知识点之间只使用“所属主题”。
- 编辑框展示固定演示主题，不定义正式身份匹配、图环规则、导入导出、备份或 AI 边界。原型代码不能直接视为生产实现。
- “演示控制与状态”提供选中身份、查询、版本、节点与所属主题的完整状态。
