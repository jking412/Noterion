## 依据与范围

- [正式规格](spec.md)、[技术记录](technical-design.md)、[领域术语](../../CONTEXT.md) 和已接受 ADR 是业务与架构依据。
- 回收站及删除后恢复已移除。删除共享知识点的规则和保留资料文件的规则继续有效。
- 核心业务 Grill 已结束；本轮询问只解决原型暴露的交互问题及尚无结论的具体边界，不重复架构选择或既定业务结论。

- Sandcastle 是独立开发流程工作，本计划不授权运行它或自动实施这些任务。

## 执行原则

- **原型**：先提供可以实际操作的具体方案，用户走查后才能确认体验；原型不算正式持久化能力已完成。
- **询问**：必须有明确的待决问题，附场景和推荐，由用户作答；代理不能代替用户把问题标为已解决。
- **技术验证**：优先复用已有研究，验证锁定版本与真实环境；形成可复现结果、适用边界及失败原因。遇到具体兼容问题时再追加针对性研究。
- **实施**：每张仍是完整用户行为，含所需数据变化、桌面交互和适用验收，不另拆纯数据库层、接口层或测试层工单。
- 表中仅列直接且必要的阻塞。编号后置不代表需要等待前面全部任务。共享接口或测试资源冲突可以影响调度，但不伪装成业务依赖。
- 旧 11、12 对应本草案 17、18，安排在主要功能之后。基本正确性随功能交付，后置的是完整故障演练和重建维护能力，不先采用会丢失修改的实现。

## 已确认的任务安排

### 01：核心桌面体验的可点击原型

**类型：** 原型；需要用户走查。

**Blocked by：** 无。

**问题与交付：** 搜索、图谱与知识点详情如何组合，才能顺畅完成“找知识点—定位—读描述—打开资料”？提供三个结构明显不同的界面方案，可以切换和点击，使用 Docker 操作、多主题共享点、同名异义的“锁”、文件和链接等固定演示数据，展示主要编辑和删除入口及图更新状态。

**完成条件：** 用户可以实际走通核心路径并比较布局；原型使用演示数据，明确哪些状态是模拟的，不连接个人正式数据。交付访问入口与待确认问题。

### 02：基于原型确认布局和关键操作

**类型：** 询问；需要用户回答。

**Blocked by：** 01：核心桌面体验的可点击原型。

**问题与交付：** 选择或组合原型方案，确认手工新建/修改入口、同名异义对象的辨认与选择、编辑共享知识点和调整所属主题的操作区别，以及删除影响的呈现。

**完成条件：** 记录用户选择、必要修改与已确认的核心交互；不要求用户逐个选择组件或控件，不重新询问已经确认的共享、同名不合并和取消回收站规则。原型如需修订，在本任务内完成后再请用户确认。

### 03：验证真实 Windows 桌面验收路径

**类型：** 技术验证；代理可独立执行。

**Blocked by：** 无，可与原型并行。

**问题与交付：** 在当前 Windows 环境中，能否构建、启动真实 Tauri 应用，并自动操作界面、经过 Rust 调用、断言可见结果？提供最小验证宿主、固定版本与命令、可复现的烟雾流程和执行证据，记录活动桌面等运行条件。

**完成条件：** 真实执行并复现一次通过的完整操作，明确环境限制。普通浏览器中的模拟 IPC 不能作为真实桌面验收通过；若验证失败，记录原因并形成具体修复或替代方案，在可用路径验证通过前不解除后续实施阻塞。

### 04：在桌面端新建、编辑并保存知识点

**类型：** 实施。

**Blocked by：** 02：基于原型确认布局和关键操作；03：验证真实 Windows 桌面验收路径。

**What to build：** 配置 PostgreSQL 后新建、修改和读取知识点名称与可选 description，关闭应用后重新打开仍能访问。同名异义可以分别保存，不自动合并。

**完成条件：** 从真实桌面操作验证持久化、独立身份及错误反馈；只有正式提交成功才确认已保存。所需 SQLx/PG 兼容性验证随本切片完成。

### 05：让知识点进入真实图谱并显示更新状态

**类型：** 实施。

**Blocked by：** 04：在桌面端新建、编辑并保存知识点。

**What to build：** 让已有与新修改的知识点可靠同步到 Neo4j，桌面图谱从 Neo4j 实际查询，选择节点查看正式描述；PG 保存与图更新分别显示状态。

**完成条件：** 业务变化与待同步记录同事务保存；应用内处理待办，退出不丢任务，重复投递不造重复节点，旧结果不覆盖新状态。固定版本的 Query API 实际读写、协议错误处理随本切片验证，不另做宽泛选型研究。

### 06：确认所属主题关系的未决边界

**类型：** 询问；需要用户回答，可与其他准备或实施分支穿插。

**Blocked by：** 01：核心桌面体验的可点击原型。

**问题与交付：** 既有规则允许一个知识点属于多个主题，但尚未约定能否属于自身、能否形成 A 属于 B 而 B 又属于 A 的循环。这会影响关系校验和主题删除。用少量具体示例展示差别，给出推荐，确认允许的关系边界及相应删除含义。

**完成条件：** 用户对这些具体未决情形作出选择，记录实施可用的约束；保留现有多主题共享、按本次删除影响处理及不全局清理的规则。可以与原型走查一起回答，无需另开通用业务访谈。

### 07：以多个主题组织同一个知识点

**类型：** 实施。

**Blocked by：** 05：让知识点进入真实图谱并显示更新状态；06：确认所属主题关系的未决边界。

**What to build：** 添加、调整、解除所属主题，从各主题访问同一节点、description 和资料入口。

**完成条件：** 从多个入口编辑后内容一致；普通解除所属关系不自动删除知识点；仅落实任务 06 已确认的关系约束。

### 08：搜索名称和描述并在图谱定位

**类型：** 实施。

**Blocked by：** 05：让知识点进入真实图谱并显示更新状态。

**What to build：** 提供片段包含和使用者可选 all/any，结果包含名称和描述摘要，选择后定位突出图谱节点并显示完整描述及已有资料入口。

**完成条件：** 用名称、仅在描述中出现的词及短中文片段验证结果；无 AI 仍可完成；PG 搜索不以 Neo4j 正常为前提，图不可用不显示为查无知识。

### 09：关联、复用并打开链接资料

**类型：** 实施。

**Blocked by：** 04：在桌面端新建、编辑并保存知识点。

**What to build：** 从知识点详情新增或选择链接资料，多对多关联、修正关联并打开外部地址。

**完成条件：** 不同知识点可使用同一资料，重启后关系仍可访问；不归档外部网页正文，不依赖对象存储分支。

### 10：验证所用对象存储接口的真实兼容性

**类型：** 技术验证；代理可独立执行。

**Blocked by：** 无，仅影响文件资料分支。

**问题与交付：** 已选对象存储路线下，本地参考服务与 Rust SDK 的固定版本能否完成本产品所需上传、读取、分片、范围读取和必要的鉴权？复用既有研究选择试验组合，在隔离测试资源中验证实际接口，记录配置、样本及结果。

**完成条件：** 成功和失败路径可复现，稳定引用可再次读取；未完成对象不标为就绪，凭据不出现在前端或日志。形成可用于文件保存与视频验证的明确、可用读取契约，不要求先配置真实云账户。仅记录不兼容不代表完成；可用组合验证通过后才解锁文件实施。

### 11：将文件保存到对象存储并重新打开

**类型：** 实施。

**Blocked by：** 04：在桌面端新建、编辑并保存知识点；10：验证所用对象存储接口的真实兼容性。

**What to build：** 配置对象服务、上传文件、关联或复用已有文件资料；重启后仍能读取，必要时通过受控缓存交系统软件打开。

**完成条件：** 本体与正式资料记录都就绪后才显示成功，上传失败如实反馈；形成内置查看共用的访问能力，资料不依赖原始本机文件仍存在。

### 12：在应用内只读查看 PDF 和图片

**类型：** 实施。

**Blocked by：** 11：将文件保存到对象存储并重新打开。

**What to build：** 从知识点资料入口内置查看 PDF 和图片，失败或不支持时提供外部打开。

**完成条件：** 实际样本可读，失败状态和兜底入口可验证；不等待视频播放分支。

### 13：验证大视频在真实 WebView 中按需读取

**类型：** 技术验证；代理可独立执行。

**Blocked by：** 03：验证真实 Windows 桌面验收路径；10：验证所用对象存储接口的真实兼容性。

**问题与交付：** 用最小播放验证程序确认选定对象读取路径在真实 Tauri/WebView 中能播放和拖动 1—2 GB 样本，且不会把整个视频送入前端内存。记录读取、内存、编码支持与兜底的证据。

**完成条件：** 支持样本可起播、拖动并按需读取；不支持编码有可行的外部打开方案；普通 GET 或无 Range 情形也检查资源使用边界。发现兼容障碍时再形成针对性研究或向用户说明实质取舍；未获得验证通过的播放路径，或用户对实质范围变更的明确答复前，不解锁相应视频实施。

### 14：保存并按需播放大视频资料

**类型：** 实施。

**Blocked by：** 11：将文件保存到对象存储并重新打开；13：验证大视频在真实 WebView 中按需读取。

**What to build：** 将已验证路径接入正式资料流程，完成大视频保存、重新打开、按需播放和拖动，失败时外部打开。

**完成条件：** 以实际 1—2 GB 样本完成桌面验收，上传中断不误报成功；不承诺全部编码、自动转码或以样本大小限定容量。

### 15：直接删除知识点并保留资料

**类型：** 实施。

**Blocked by：** 08：搜索名称和描述并在图谱定位；09：关联、复用并打开链接资料；11：将文件保存到对象存储并重新打开。

**What to build：** 先处理没有下属知识点的明确删除；移除知识点、description 和相关连接，资料本体仍保存并可关联其他知识点。

**完成条件：** 搜索、详情及赶上同步的图中均不再出现已删点；删除变化可靠传播，旧事件不复活节点；不提供回收站或恢复。

### 16：删除主题并按归属规则处理下属知识点

**类型：** 实施。

**Blocked by：** 07：以多个主题组织同一个知识点；15：直接删除知识点并保留资料。

**What to build：** 保留仍属于其他保留主题的共享知识点，移除因本次主题删除失去全部所属主题的受影响下属节点，保留资料文件。

**完成条件：** 独立知识点不受全局清理，普通解除关系不套用主题删除级联；按任务 06 确认的关系边界验证复杂情形。

### 17：完整验证 Neo4j 故障下的使用与同步追赶

**类型：** 实施与故障验收；建议排在主要功能之后。

**Blocked by：** 08：搜索名称和描述并在图谱定位；09：关联、复用并打开链接资料；11：将文件保存到对象存储并重新打开。

**What to build：** 在已有基本可靠同步上，补齐跨功能的故障反馈、追赶和恢复闭环，演练图库停用时的保存、搜索、阅读、资料访问与应用重启。

**完成条件：** 其他必要组件正常时核心使用继续，图不可用如实显示；持久待办在重启后续处理，赶上后恢复图功能，无重复或旧数据回退。本任务不作为前面普通功能的阻塞。

### 18：提供从 PostgreSQL 重建图谱的维护能力

**类型：** 实施；建议排在主要功能之后。

**Blocked by：** 16：删除主题并按归属规则处理下属知识点；17：完整验证 Neo4j 故障下的使用与同步追赶。

**What to build：** 提供维护入口重建 Neo4j，如实显示进度、失败和可用状态，协调重建期间的正式修改。

**完成条件：** 重建后节点身份、所属主题与资料入口一致；已删除知识点不复活，不要求重新录入；副本赶上正式状态后再报告图功能恢复。

## 优先安排

1. 先启动核心体验原型与 Windows 验收验证；对象接口验证可同时推进，不挡知识点和搜索。
2. 原型走查确认后，优先做知识点、图谱、搜索与链接资料；关系边界的局部询问只阻塞多主题及其后续主题删除。
3. 文件分支在对象验证通过后推进；PDF/图片与视频技术验证、实施按各自依赖并行。
4. 普通删除和主题删除在对应基础功能具备后交付。
5. 最后集中完成跨功能故障演练与重建维护能力；期间各功能已有的基本保存和同步正确性不能省略。

只有出现具体尚未解决的问题，才追加相应询问、研究或原型任务，并只阻塞真正受影响的分支。探索结果若改变已拟实施范围，应先修订受影响工单及其依据，再执行。
