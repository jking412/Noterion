# PostgreSQL 保存正式业务数据，Neo4j 提供可重建图查询副本

项目采用方案 A：PostgreSQL 保存完整的结构化业务事实，包括知识点、description、知识关系、资料信息与关联，以及必要的导入记录和图同步待办；Neo4j 保存由这些事实生成的图查询表示。正式业务修改以 PostgreSQL 为准，Neo4j 不保存无法从正式记录重建的独有业务事实。

用户在比较图查询副本与图领域独立主存后选择 A，理由是需求仍在细化，希望保留统一的数据依据，避免过早将正式数据分散到两个数据库。项目接受部分图数据重复保存及可靠同步的工程成本，以便在调整需求和图表示时有明确的事实来源；Neo4j 继续承担实际的图查询。

后续用户已确认：PostgreSQL 正式提交后先提示保存成功，图更新显示独立状态；Neo4j 临时不可用、其他所需组件正常时，仍允许核心保存、名称/description 搜索、详情阅读和资料打开，图浏览与定位明确提示暂不可用。图服务恢复后须确认副本已赶上正式数据，再恢复相应图功能。具体投递机制、同步时限与刷新实现仍待工程设计。

Q22 进一步选择图同步任务在 Tauri/Rust 桌面应用内运行，应用完全退出后暂停，未完成工作持久保留在 PostgreSQL，下次启动继续处理。用户希望结构尽量简单，因此接受退出后的同步暂停，省去独立常驻 worker 的部署与维护；若未来出现应用外持续写入或退出后继续同步的实际需求，再重审运行位置。具体待办表、批次、幂等与重试仍由工程设计确定。

文件资料本体随后已由 [ADR 0003](0003-use-configurable-object-storage.md) 确定为可配置对象存储，PG 仍保存权威结构化资料信息与关联。本决策不构成应用实现授权。

工单拆分阶段的范围更正（2026-11-07）：用户明确移除回收站及删除后恢复。同步仍须可靠传播删除，并防止重试或重建使已删节点复活；必要的技术删除记录不构成用户回收站，不新增可恢复业务副本。
