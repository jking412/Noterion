# Issue #26 AI 状态回归

日期：2026-11-13（Asia/Shanghai）。本记录覆盖前端公开 `useAiTasks()` 的状态行为与原生接收计数清理；真实 Windows 客户端的截图、供应商请求和取消证据另见本 Issue 的桌面验收记录。这里的单元测试不作为真实 IPC 或 DeepSeek 验收证据。

固定审查基点：`647c20566550a86056b0e6b2def81ef36e71d4fe`。

## 已确认的测试边界

测试从公开 `useAiTasks()` 接口启动、取消、重试任务，观察它向组件提供的状态。Vue 使用真实响应式和挂载/卸载生命周期；唯一可控替身是系统外部的 Tauri Channel/invoke 边界，用来精确安排晚到的任务响应。测试没有依赖 composable 私有变量，也没有为静态文案或样式创建镜像测试。

文件：`app/src/composables/useAiTasks.test.ts`。

## 取消竞态：先红后绿

最小触发顺序：启动 A → 取消 A（原生取消请求暂未返回）→ 启动 B → B 成功 → A 的取消请求失败。

红色复现命令，在本 worktree 的 `app/` 中执行：

```powershell
npm.cmd test -- src/composables/useAiTasks.test.ts
```

首次结果为 **1 failed / 1 test**：

```text
keeps a newer completed result when cancellation of the previous task fails late
AssertionError: expected '上一任务的取消通道已关闭' to be ''
```

按 diagnosing-bugs 流程，在修复前提出并核对的假设：

| 排序 | 可证伪假设 | 预测与观察 |
| --- | --- | --- |
| 1 | 旧取消请求的 catch 缺少任务代际检查 | 仅给此 catch 添加 epoch 检查应转绿；最小修改后 1/1 通过。 |
| 2 | 新任务主动继承了旧错误 | 若成立，不需要旧取消 Promise 拒绝也会出现错误；最小用例中的 B 没有任何错误事件，错误来自后来的拒绝。 |
| 3 | A 的旧结果事件串入 B | 若成立，必须有 A 的结果事件；该用例没有发送任何 A 结果事件，仍能复现。 |

确认原因是第一项：`cancel()` 的异步 catch 不受原有 generation 防护约束。现仅当前代际可以写入取消失败；同一任务取消失败显示“未完成”和实际错误，不再保留“已取消”的终态说明。新任务的成功结果不受旧取消失败影响。

## 等待反馈：先红后绿

同一命令随后增加三种任务的公开状态检查：等待中送入 `receiving`、`validating` 及内部 detail/delta，等待状态应保持一致，不能将内部片段当成最终结果。

修改前结果为 **3 failed / 4 tests**，三种任务均复现等待标签由“正在连接 DeepSeek”跳到“正在接收模型结果”。

修改后按请求任务使用稳定的一条等待文案：

- 自动解析：“正在整理知识”。
- 自动查找：“正在查找知识”。
- 自动回答：“正在生成回答”。

界面不再消费内部 detail/delta。Rust `Task` 删除接收字符计数与每 160 字的 receiving 事件；SSE 继续真实接收、累积结构化输出并在解析完成后校验，读取时仍检查取消。未新增流式回答、伪造推理文本、百分比或计时进度。

## 最终检查

该测试文件最终为 **8/8 通过**：

1. 三种任务各自的等待状态保持稳定，内部片段不会成为结果（3 条）。
2. 旧取消请求的晚失败不覆盖新任务成功结果。
3. 已取消任务的晚结果/错误不覆盖新请求。
4. 用户在启动响应前取消，收到真实任务 ID 后仍向原生边界发送取消。
5. 当前任务取消失败显示错误，不声称取消成功。
6. 失败保留问题，重试清除旧错误并可正常完成。

`npm.cmd run typecheck` 与 `git diff --check` 通过。单元测试未连接官方模型；真实供应商响应、网络/鉴权/限流、慢响应和请求中止由桌面验收覆盖并单独声明边界。

`cargo fmt --manifest-path app/src-tauri/Cargo.toml --check` 在此代理的受限进程内因 cwd canonicalize“拒绝访问”未执行完成；交由主实施代理在其构建环境运行最终 Rust 检查，不能将此项记为通过。

知识助手保留原有结果历史语义：再次提交时，上一结果及其原问题移入可展开的会话历史。取消/失败后仍可查阅；当前结果区域清空，避免将旧答案显示为新问题的回答。另一处解析任务运行时，知识助手显示单独的“查看任务”入口并冻结本次 AI 操作，取消入口只出现在实际任务所属的界面。输入使用 readonly，可继续选择和复制。
